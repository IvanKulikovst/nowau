# Приложение «Регламент-ТС» для Windows (Electron)

Оболочка вокруг `index.html`: программа открывается в собственном окне (не в браузере), а данные хранятся в **обычных файлах**, а не в хранилище браузера.

## Где лежат данные

| Режим | Папка данных |
|---|---|
| Установленное приложение | `Документы\Регламент-ТС` (можно сменить: «Сохранность данных → Файлы данных приложения») |
| Переносная версия | `Данные Регламент-ТС\db` рядом с программой |

Внутри папки:

* `db.json` — все записи учёта (основной файл);
* `db.prev.json` — предыдущая версия `db.json`;
* `backups/` — суточные копии, последние 14;
* `files/` — вложения к записям ТО;
* `snapshots/` — точки восстановления.

Запись `db.json` атомарная (временный файл → переименование), перед каждой записью предыдущая версия копируется в `db.prev.json`. Если файл окажется повреждённым, приложение само берёт `db.prev.json`, а при его неисправности — последнюю суточную копию; повреждённый файл сохраняется рядом как `db.corrupt-*.json`, пользователь видит предупреждение.

## Как это устроено

* `main.js` — окно, меню, обработка сообщений от программы, папка данных, переносной режим.
* `preload.js` — безопасный мост `window.TSTNative` (изоляция контекста, песочница): программа получает только функции чтения и записи файлов данных.
* `storage.js` — работа с файлами без Electron (покрыта обычными тестами Node).
* `index.html` программы остаётся тем же файлом; в браузере она работает как раньше, а в приложении определяет мост и пишет в файлы (раздел 27g в коде).

## Разработка

```
cd app
npm install
npm start               # запуск приложения (index.html берётся из корня репозитория)
npm test                # тесты файлового хранилища
xvfb-run -a node test/e2e.test.js   # сквозной тест на Linux (нужен виртуальный экран); на Windows — node test/e2e.test.js
```

## Сборка установщика

**Основной путь — GitHub Actions** (`.github/workflows/build-windows.yml`): при каждом изменении программы собирается установщик `Reglament-TS-Setup-<версия>.exe` и переносная версия на сервере с Windows; файлы берутся из раздела Actions → запуск → Artifacts. По тегу `v*` они прикрепляются к релизу.

**Локально на Windows:** `npm run dist` → `dist\Reglament-TS-Setup-*.exe` и `dist\Reglament-TS-Portable-*.exe` (electron-builder).

**Локально на Linux (без Wine):**

```
npm run dist:dir -- -c.win.signAndEditExecutable=false
node scripts/build-installer.js      # установщик на NSIS + переносной zip
```

Собственный установщик (`installer/installer.nsi`) ставит без прав администратора в `%LOCALAPPDATA%\Programs\Регламент-ТС`, создаёт ярлыки на рабочем столе и в меню «Пуск», регистрируется в «Приложениях и возможностях»; при удалении данные в «Документах» не затрагиваются.

## Ограничения

* Только Windows 10/11, 64 бита. Размер установщика около 100 МБ — в него входит собственный браузерный движок.
* Приложение **не подписано** сертификатом: Windows SmartScreen при первом запуске покажет «Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае». Подпись требует платного сертификата.
* Обновление — запуск нового установщика поверх старого; данные сохраняются.
